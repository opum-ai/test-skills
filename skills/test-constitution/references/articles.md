# The articles: rationale, sources, enforcement

| Art. | Rule | Why (evidence) | Standards / practice | Enforced by |
|---|---|---|---|---|
| I | Every test protects a named behavior | Tests that can't name a purpose become change detectors; traceability lets risk drive depth | ISTQB CTFL §1.4.4 (traceability to risks → residual risk); NASA SWE-052 (bidirectional, R5) | audit review; R4+ requirement ids |
| II | Finite budgets; a per-change limit; a downward ratchet | Agents add tests on every change and don't prune (Hora & Robbes 2026; TEBench 36% F1 stale detection); suites 4× in a year (Linear) | ISTQB CTAL-TA "balance coverage with a manageable size"; DORA ~10-minute feedback | gate: `max_tests`, `max_suite_seconds`, `max_new_tests_per_pr`, baseline |
| III | Adequacy is risk-tiered mutation score; coverage is a diagnostic | Coverage correlates weakly with effectiveness (Inozemtseva & Holmes); mutants couple to real faults (Just et al.) | ISO/IEC/IEEE 29119-2 risk-based; Google 60/75/90, >90% "not worth it"; AWS "over-indexing on coverage" anti-pattern; NIST IR 8397 "high coverage guarantees little" | gate: tier `min_mutation_score`, rigor floors |
| IV | Every test can fail, with spec-anchored oracles | LLM oracles encode actual rather than expected behavior; state-anchored oracles cancel faults (Canedo 2026); tautological agent tests (Böckeler) | ISTQB "absence-of-defects fallacy" | gate smells: no-assertion, tautology, swallowed-exception |
| V | Admission by marginal value | TestGen-LLM keeps only tests that add coverage; ACH is mutation-guided; JiTTest's catching vs hardening split | ISTQB "tests wear out"; CTAL-TAE "remove duplication" | gate: `require_unique_kill` (matrix) |
| VI | Behavior, not implementation; mock at boundaries | Agents over-mock (36% vs 26%); change-detector tests have negative value (Google TotT); Khorikov: resistance to refactoring is binary | spec-kit Article IX (real dependencies over mocks) | gate: `max_mocks_per_test`; R4 `implementation-coupled` |
| VII | Generalize before enumerating | One PBT kills about 50× more mutants than an average unit test (OOPSLA 2025); daily.dev's "does the code branch on it?" rule | 29119-4 equivalence partitioning, BVA, combinatorial; NIST t-way | clones report; test-plan partition models |
| VIII | Proof over enumeration, plus one conformance test | Cedar: proofs plus about 100M nightly differential tests; AWS IAM: 10^15 shadow samples; MongoDB: 4,913 model-generated tests | AWS systems-correctness portfolio; NASA formal methods at high criticality | coverage-proof claims |
| IX | Red → Green → Refactor → Prune; catching tests are ephemeral | Agent tests barely change outcomes (arXiv 2602.07900); JiTTest drops per-diff tests | — | agent block, hook, test-plan report `+N/−M` |
| X | Small by default; larger tests few and tiered | Google test sizes; Vocke: "push tests down"; the ice-cream-cone anti-pattern | SWE@Google ch. 11; Bazel timeouts by size | gate: `sleep` smell, time budget; test-ci tiers |
| XI | Flakiness is a defect: quarantine, fix or delete | ~1% flakiness destroys value (Google; ~0.15% actual); 45% of flakes are async-wait (Luo) | DORA "don't tolerate flaky tests"; ISTQB TAE "move unreliable tests out"; GitLab 3-day/3-month lifecycle | gate: quarantine age, `max_skipped` |
| XII | Certified deletion, demote before delete | Kill-set reduction keeps kills (Shi 2014) but real misses reached 52% (Shi 2018); deletion is the classic agent cheat (Beck) | Google TAP / Meta PTS: run less before deleting | tmx certificate, verify, compare; probation |
| XIII | Amendments with reasons; the gate on every change; agents never waive R4/R5 | Machine-enforced manifestos beat prose (Hasanli 2026); hooks beat instructions (Claude Code docs) | 29119-4 tailored conformance with justification; NASA SWE-219 deviations need approval | amendment log; gate; approvals from the review record |
